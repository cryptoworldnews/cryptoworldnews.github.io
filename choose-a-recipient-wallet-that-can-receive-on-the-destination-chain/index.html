Choose a Recipient Wallet That Can Receive on the Destination Chain

Choose a recipient wallet that supports the destination chain and token; verify its address format, any required memo, and the bridge route before sending.

Merkle Street NewsroomSep 30, 2026#08363a3 min read

Choose a recipient wallet by checking that it can receive the asset on the destination chain and that its address matches the format that chain accepts. A bridge moves value between networks: you choose a route, connect or provide a source wallet, enter a destination address, then approve or send the transfer. Depending on the bridge, a contract may lock or burn tokens on the source chain and release or mint an equivalent on the destination. The recipient field tells the bridge where to deliver the result.

The destination address may look familiar without being safe to reuse. Some wallets show the same address on several compatible networks, but assets on one network do not automatically appear on another. For route-specific steps, see this guide to Manta Bridge ETH and token transfers. The general check is the same: confirm the destination network and asset before you copy an address.

Should I use the same wallet on both chains?

Use the same wallet only if it supports the destination network and can control the address there. A wallet is software or a service for managing keys; the address is the destination recorded in the transfer. On compatible networks, one wallet may derive the same address for each network, but that does not mean every asset or network is supported by the wallet interface.

Before bridging, check that you can select or add the destination network in the wallet, and that the token can be displayed or managed there. If the wallet does not support that chain, the transfer might arrive at the address but be difficult to access. A different wallet can be used if it supports the destination chain and you can securely control its receiving address. The important match is between the bridge’s destination network and a wallet that can operate there.

What should I check in the recipient field?

Check the address against the destination wallet, not a source-chain account label or an address copied from an old transfer. Then compare the network and asset shown on the bridge with the network and asset expected by the recipient. Some chains and services also require a memo, tag, or other identifier in addition to an address; if the destination asks for one, include it exactly as shown.

  • Confirm the destination network in both the bridge and wallet.
  • Copy the receiving address from the wallet while viewing that network.
  • Check whether the recipient requires a memo or tag, especially if it is a hosted account.
  • Make sure the bridge route delivers the token you expect, since a token’s name can appear on more than one network.

For a wallet you control, the address is usually enough only when the chain and token are supported. An exchange or other hosted service may use a shared deposit address and rely on a memo to credit the right account. Treat its deposit instructions as specific to that asset and network. Never assume that an address accepting a token on one chain will accept it on another.

How do I reduce the chance of a wrong transfer?

Review the bridge’s final confirmation screen before approving the transaction. It should show the source network, destination network, asset, amount, and recipient. If any field differs from your intended transfer, stop and correct it before signing. A bridge cannot generally redirect a completed transfer just because the destination address was mistyped.

When the route or wallet is unfamiliar, a small test transfer can help confirm that the destination setup works, though it may involve another transaction fee. Wait for the bridge’s stated completion process and check the destination wallet on the correct network. The safer default is a wallet you control that explicitly supports the destination chain, with the address copied from that chain’s receiving screen.
