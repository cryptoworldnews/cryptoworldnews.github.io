LI.FI Explorer’s Missing Transaction: A Hash Check

When LI.FI Explorer says transaction not found, the hash may be pending, on another chain, or an approval rather than the confirmed bridge transfer.

Merkle Street NewsroomNov 28, 2026 · 06:19 UTC#bc079c3 min read

LI.FI Explorer returns no result when a hash is not yet a confirmed transaction sent to a LI.FI contract on the source chain. The hash may belong to a pending transfer, a different network, or a token approval that happened before the bridge transaction.

Start with the chain where the transfer began. A lifi bridge transfer is sent to the LI.FI Diamond contract on that source chain, and LI.FI Explorer indexes confirmed transactions sent to LI.FI contracts. The lifi bridge topic explains how route choice, fees, and transfer time fit into a move between chains.

How to tell what the hash belongs to

A source-chain block explorer shows what the hash actually did. Open the block explorer for the chain selected in the wallet when you started the transfer, then search the hash there. Check its status and the destination address shown in the transaction details.

When the block explorer cannot find the hash either, the transaction is pending or dropped. In either case, there is no confirmed source-chain transaction showing that funds left for the bridge. A pending wallet submission may still be waiting to confirm; a dropped one did not make it on-chain. Check the wallet’s activity and the selected network before trying again.

A confirmed transaction sent to the token contract is usually a token approval. An approval lets a contract spend a specified token amount; it is a separate transaction from the transfer itself. Think of it as granting access before sending an instruction: the approval permits the later bridge step, but does not carry out that step.

This is the common reason a wallet hash fails in LI.FI Explorer. The wallet may show the approval first, so that is the hash a user copies. Look at the next wallet transaction after the approval. The bridge transaction should be sent to the LI.FI Diamond on the source chain. Search for that transaction’s hash in LI.FI Explorer.

If there is no later transaction to the LI.FI Diamond, the bridge step still needs to be sent. An approval alone does not start the transfer. Return to the wallet’s activity and find whether the transfer submission followed it; do not treat an approval’s confirmation as proof that the cross-chain move began.

What a confirmed LI.FI Diamond transaction means

A confirmed transaction addressed to the LI.FI Diamond is the source-chain bridge step. Make sure the block explorer shows the same hash and source network you entered in LI.FI Explorer. If both match, wait a few minutes and search again; the Explorer may not show a newly confirmed transaction immediately.

The block explorer is the first check because it answers whether the source-chain transaction exists, whether it confirmed, and which contract received it. LI.FI Explorer answers a narrower question: whether it has indexed a confirmed transaction sent to a LI.FI contract. A missing result by itself does not tell you that funds are lost.

For a lifi bridge transfer, use the source-chain record to identify the right hash: pending or absent means no confirmed bridge transaction yet; a token-contract destination points to the approval; a confirmed LI.FI Diamond destination is the hash to retry in LI.FI Explorer after a short wait.
