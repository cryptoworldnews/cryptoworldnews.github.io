How to Reconcile Treasury Deposits to Polygon

Match each treasury deposit to its Polygon transaction, token and destination address so bridge transfers, direct payments and fees land in the right records.

Merkle Street NewsroomOct 22, 2026 · 22:27 UTC#da0e1f4 min read

Reconcile a treasury deposit to Polygon by matching the intended transfer to its on-chain transaction, then recording the amount that arrived and any fee separately. A treasury ledger may start with a payment instruction, but the chain records what actually happened: which address sent the tokens, which address received them, and which token contract moved them. The reconciliation joins those records.

What counts as a deposit to Polygon?

A deposit can arrive through a bridge or as a transfer already on Polygon. Those paths create different evidence. In a bridge transfer, a user sends tokens on a source chain to a bridge contract; the bridge records the deposit, then the corresponding tokens become available at the destination address on Polygon. A direct Polygon transfer has no source-chain bridge step: the sender’s transaction transfers tokens to the treasury address on Polygon.

That distinction matters because the source-chain transaction is not itself proof that the treasury received funds on Polygon. The step-by-step Polygon Bridge transfer explanation covers the movement between chains in more detail. For reconciliation, treat the bridge transaction as the start of a trail and confirm the destination-side receipt before marking the deposit complete.

Think of a bridge transfer like a parcel with two tracking scans: dispatch on one chain and delivery on another. The analogy ends there. The actual records are transactions, token contracts, addresses and amounts, and the two scans may not appear at the same time.

Which records should you match?

Start with the treasury instruction or expected deposit record, then find the Polygon transaction that matches it. A useful record should identify the network, transaction hash, token, destination address, amount and status. For a bridged deposit, keep the source-chain hash too, and link the two transactions using the bridge’s deposit or transfer reference when available.

  • Network: Confirm the destination is Polygon and, for a bridge, note the source chain separately.
  • Address: Check the receiving address against the treasury’s approved address list.
  • Token: Match the token contract, not just its ticker or display name; different contracts can use similar names.
  • Amount and fee: Compare the received token amount with the expected amount, and record transaction fees as their own entries.

Use the transaction hash to inspect the relevant chain record. For a direct transfer, confirm the transaction succeeded and that its token transfer event names the treasury address as recipient. For a bridge, confirm the source deposit and then find the destination-side transfer or balance credit. A submitted transaction can fail, and a source-side success alone does not establish that the Polygon-side deposit is complete.

How should you handle mismatches?

Post a deposit only when the on-chain receipt matches the intended treasury entry closely enough to identify it. If the amount differs, record the received amount and investigate the difference; do not force the ledger to equal the instruction. Network fees, token decimals, partial transfers or a wrong destination can explain a mismatch, but the transaction record must support the explanation.

Keep unmatched items in a review queue with their hashes, addresses and observed amounts. This makes pending bridge transfers visible without counting them as available Polygon funds. When the destination receipt appears, link it to the original instruction and close the item. If no matching receipt appears, leave the deposit unresolved and investigate the address, token contract and transaction status.

For a recurring treasury, reconcile by transaction rather than by comparing only end-of-day wallet balances. A balance can include older deposits, outgoing payments and other activity. A transaction-level trail shows which instruction each receipt satisfies, while preserving fees and exceptions as separate records. The result is a ledger that explains both what the treasury expected and what Polygon actually received.
